## 主要调用关系

训练流程：

```text
tools/train.py
  → src/engine/application.py：加载四层配置，注册并创建业务子类
  → adapter.run_training()：通过统一接口调用公共调度
  → src/engine/trainer.py：train 数据前后向、优化器和 EMA 更新
  → adapter.build_model / build_criterion / build_dataloader：按对象类型使用相应实现
  → val 验证与 adapter.select_operating_point()：选权重、选置信度
  → ExperimentStore：独立保存配置、日志、best/last 和工作点
```

推理与评估流程：

```text
tools/infer.py 或 tools/eval.py
  → application.setup()：选择业务配置和子类
  → DetectionRuntime：记录原图尺寸，按本任务要求预处理
  → InferenceBackend.predict()：PyTorchBackend 或 TensorRTBackend 实际执行
  → adapter.postprocess()：解码、原图坐标还原、阈值及可选 NMS
  → Detection：统一的 boxes / scores / labels
  → adapter.evaluate()：小目标使用 Pd/Fa，识别任务有自己的评估策略
```

同一接口调用由具体对象决定实现，就是这里的多态。父类复用公共流程，子类覆盖需要保留差异的方法。输入高宽、类别、网络规模、损失、增强、阈值和权重从各任务配置或实例读取，分别维护。

## 权重、引擎和结果文件的区别

| 文件或类型 | 含义 |
|---|---|
| pretrained/v2_s_coco.pth | 新训练的预训练起点 |
| texture_v2_s_imported/weights/best.pth | 当前默认已训练小目标推理权重 |
| 新正式训练生成的 last.pth | 完整恢复状态，通常包含模型、EMA、优化器、调度、随机状态等；本交付的 resume_validation 没有保留这类权重 |
| model.onnx | 已导出的计算图和参数，供部署工具读取 |
| model_fp16.engine | TensorRT 构建后的推理引擎，与构建环境和设备相关 |
| model_fp16.build.json | 引擎构建身份、精度、GPU 及文件指纹，随对应引擎使用 |
| timing.cache | TensorRT 构建策略测速缓存 |
| resolved.yaml / classes.json | 实验实际配置与类别映射快照 |
| history.jsonl | 每行一个事件/轮次的日志，按行查看训练过程 |
| operating_point.json / frozen_task.yaml | 验证集选出的工作点及可复用部署配置 |
| *_test.json / *.predictions.json | 汇总结果 / 逐图预测记录，用于复核而非训练初始化 |

小目标 Pd = TP/(TP+FN)，Fa = FP/(TP+FP)，代码返回 0～1 的比例。现有文件里的测试指标属于已完成实验的回归记录；resume_validation 的短流程指标只用于确认程序衔接。本机测速来自 GTX1650Ti 单模型，正式 Orin 三模型并发仍需在目标设备实测。当前目录没有交付已完成的真实连续五帧算法或基于新域的迁移/增量训练实验。
